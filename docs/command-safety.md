# Command Safety

## Hard Rules

- Never delete files automatically.
- Never change firewall rules automatically.
- Never reboot automatically unless explicitly approved.
- Never edit OpenVPN, SSH, Docker, or system configuration files without approval.
- Never expose ports automatically.
- Never run arbitrary shell commands generated by an LLM.
- Never place an OpenAI API key or other controller secret on a managed server.
- Never install or replace server scripts without explicit user approval.

## Allowed Execution Model

All server-side commands must be represented by predefined action IDs in the controller action registry.

An LLM or Codex may recommend an action, but executable actions must map to a local controller definition:

```text
recommendation -> action_id -> registry lookup -> policy check -> approval check -> execution
```

Free-form commands from an LLM response are advisory text only and must not be executed against servers.

## Risk Levels

### read_only

Allowed by default.

Examples:

- collect health summary
- check disk usage
- check service status
- check update counts
- inspect Docker container status

### low_risk

May be allowed automatically only if policy explicitly enables it.

Examples:

- refresh apt package metadata
- collect a journal summary
- run a non-mutating Docker inspection command

### approval_required

Requires explicit human approval every time.

Examples:

- restart a service
- restart a Docker container
- apply security updates
- prune Docker images or build cache
- reboot a server

### forbidden

Must not be exposed through the controller.

Examples:

- recursive deletes
- firewall rule changes
- SSH configuration edits
- OpenVPN configuration edits
- Docker daemon configuration edits
- arbitrary shell command execution
- automatic port exposure

## Approval Standard

Approval must be specific. A valid approval identifies:

- server ID
- action ID
- key arguments
- known risk

Example:

```text
Approve action restart_docker_container on container-host for container homepage.
```

## Audit Trail

Every action attempt should write an action history record containing:

- timestamp
- server ID
- action ID
- arguments
- risk level
- approval source
- command or script path executed
- exit code
- stdout summary
- stderr summary

## Script Deployment

The first implementation expects server scripts to already be installed on each server at the configured remote path.

Future deployment support must be explicit and approval-based. A deployment command may copy known repository scripts to a configured directory, but it must not copy arbitrary generated commands or mutate system configuration.
